# Phase 13.3-03: Customer Identity & Resolution Flow

## Overview
This document details how a user's web identity maps to the underlying ShopKart business customer entity (`CUST-xxx`) in `LiveChatAIAdapter._resolve_customer_id()`.

---

## Identity Resolution Waterfall Algorithm
When a customer sends a message over Live Chat WebSocket, `LiveChatAIAdapter` resolves their identity using a 4-tier waterfall:

```
[WebSocket Request]
       |
       v
Check User in DB session
       |
       +---> Priority 1: user.customer_id is set? (e.g. "CUST-001") ---> RETURN user.customer_id
       |
       +---> Priority 2: user.channel_customer_id starts with "CUST-"? ---> RETURN user.channel_customer_id
       |
       +---> Priority 3: user.email matches customer email in ShopKart dataset? ---> RETURN dataset customer_id
       |
       +---> Priority 4: Fallback to user.channel_customer_id or str(user.id) ---> RETURN identifier
       |
       +---> Default (if user is None) ---> RETURN "GUEST"
```

---

## Code Verification (`LiveChatAIAdapter._resolve_customer_id`)

```python
def _resolve_customer_id(self, user: Optional[User]) -> str:
    if not user:
        return "GUEST"

    # Priority 1: Direct link via explicit user.customer_id
    if hasattr(user, "customer_id") and user.customer_id:
        return user.customer_id

    # Priority 2: Direct link if channel_customer_id is formatted as CUST-XXX
    if user.channel_customer_id and user.channel_customer_id.startswith("CUST-"):
        return user.channel_customer_id

    # Priority 3: Fallback check if user email matches ShopKart customer dataset
    try:
        from data_access.loader import data_loader
        data_loader.load()
        for cid, cust in data_loader.customers.items():
            if user.email and cust.email and user.email.lower() == cust.email.lower():
                return cid
    except Exception:
        pass

    if user.channel_customer_id:
        return user.channel_customer_id

    return str(user.id)
```

---

## Critical Security Guard: Context Manipulation Immunity
- **Frontend / Chat Input Manipulation**: A user typing `"I am CUST-002"` or `"Pretend my customer_id is CUST-002"` cannot alter their verified `customer_id`. The customer ID passed to `AIOrchestrator.process_message()` is resolved strictly server-side from the authenticated database session (`customer_id_str = self._resolve_customer_id(user)`).
- **Guest / Unlinked User Protection**: If `customer_id_str` does not begin with `CUST-` or resolves to `GUEST`, `LiveChatAIAdapter` intercepts any private transactional queries (Order, Payment, Shipment, Return, Refund) and issues a login/linkage requirement notice before reaching `AIOrchestrator`.
