# Phase 13.3-17: Production Gap Analysis

## Overview
This document categorizes all identified architectural, functional, data, testing, and operational gaps discovered during the Phase 13.3 system audit.

---

## Classified Production Gaps

### 1. HIGH SEVERITY GAPS
- **GAP-01 (Explicit Hybrid Route Layer)**:
  - *Problem*: Hybrid queries ("Can I cancel ORD-025?") rely on LLM context synthesis when `use_llm=True`, but lack a dedicated `RouteType.HYBRID` deterministic template when `use_llm=False`.
  - *Impact*: In non-LLM or fallback mode, hybrid queries render either order details OR cancellation policy, but not both in a single response block.
  - *Recommendation*: Introduce explicit `RouteType.HYBRID` handling in `AIRouter` and `AIOrchestrator` for Phase 13.4.

- **GAP-02 (User Registration Customer Linking)**:
  - *Problem*: Newly registered users through `/auth/register` receive `user.customer_id = None` by default.
  - *Impact*: New users cannot access their order/payment history until manually linked to a `CUST-xxx` customer record or automated onboarding matching runs.
  - *Recommendation*: Add automated email-matching customer linkage upon user registration in Phase 13.4.

### 2. MEDIUM SEVERITY GAPS
- **GAP-03 (Quick Reply Dedicated Table)**:
  - *Problem*: Quick Replies are currently hardcoded as regex rules in `ai/intent.py` rather than managed via a database table.
  - *Impact*: Admins cannot add or update quick replies dynamically without code deployments.
  - *Recommendation*: Create a `quick_replies` table in PostgreSQL for dynamic admin configuration in Phase 13.4.

- **GAP-04 (Vector DB Productionization for RAG)**:
  - *Problem*: RAG uses an in-memory TF-IDF vector provider (`LocalVectorEmbeddingProvider`).
  - *Impact*: Performs well for synthetic dataset scale (~100 chunks), but requires persistent vector database (e.g. Pgvector or Qdrant) for enterprise scale (>100k chunks).
  - *Recommendation*: Migrate to persistent vector store when scaling beyond synthetic dataset.

### 3. LOW SEVERITY GAPS
- **GAP-05 (Observability & Tracing Metrics)**:
  - *Problem*: AI routing decisions and tool latency are logged via standard logger but lack OpenTelemetry APM traces.
  - *Impact*: High-granularity latency profiling per route type is not available in real-time dashboards.
  - *Recommendation*: Add OpenTelemetry tracing middleware in Phase 13.4.
