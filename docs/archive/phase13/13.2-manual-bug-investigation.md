# Phase 13.2 Manual Validation Bug Investigation Report

**Final Status**: `ROOT_CAUSE_IDENTIFIED`

---

## 1. Issue Summary

During manual validation testing of Phase 13.2, two behavioral anomalies were discovered:

1. **Observed Issue 1 (Stale / Incorrect Shipment Response)**:
   When an authenticated customer submits sequential queries:
   - Query 1: `"Is PROD-001 available?"` $\rightarrow$ Product availability response returned.
   - Query 2: `"Where is my shipment?"` $\rightarrow$ Stale response for `PROD-001` returned again instead of shipment tracking details.

2. **Observed Issue 2 (Product MRP Becomes Zero)**:
   Product queries for `PROD-001` and `PROD-002` return `Price: ₹46,999.00 (MRP: ₹0.00, Discount: 0.0%)` and `Price: ₹27,499.00 (MRP: ₹0.00, Discount: 0.0%)` despite the source `products.json` dataset defining explicit positive MRP values (`₹54,999.00` and `₹32,999.00` respectively).

---

## 2. Reproduction & Execution Trace

### Reproduction Steps

1. Initialize `AIOrchestrator(use_llm=False)`.
2. Execute Turn 1 as `customer_id="CUST-001"`:
   `orchestrator.process_message("Is PROD-001 available?", customer_id="CUST-001", conversation_id="conv_test_123")`
   - **Response**: Returns details for `PROD-001` (Price ₹46,999, MRP ₹0.00).
   - **Context State**: `active_product_id` set to `"PROD-001"`.
3. Execute Turn 2 in the same conversation session:
   `orchestrator.process_message("Where is my shipment?", customer_id="CUST-001", conversation_id="conv_test_123")`
   - **Actual Response**: Returns details for `PROD-001` again.
   - **Expected Response**: Returns shipment tracking status for `CUST-001`'s order.

### Actual Internal Execution Trace for Turn 2 ("Where is my shipment?")

1. **Input Context Slots**: `{'order_id': None, 'product_id': 'PROD-001', 'return_id': None, 'refund_id': None}`
2. **Intent Classification**:
   - `IntentClassifier.classify()` merges `context_slots` into query entities $\rightarrow$ `entities = {'product_id': 'PROD-001'}`.
   - Pattern matching fails to detect `SHIPMENT_INQUIRY` because `"where is my shipment"` is missing from `SHIPMENT_INQUIRY` keyword rules.
   - Evaluation falls through to `PRODUCT_INQUIRY` (Step 11), where `if "product_id" in entities:` evaluates to **`True`** (inherited from context).
   - **Detected Intent**: `PRODUCT_INQUIRY` (Category: `product`).
3. **Route**: `STRUCTURED`
4. **Target Tools**: `['get_product']`
5. **Tool Arguments**: `product_id="PROD-001"`
6. **Executed Tool Result**: `{'product': {'product_id': 'PROD-001', 'price': 46999.0, 'mrp': 0.0, ...}}`
7. **Final Response Source**: `ResponseSynthesizer.synthesize_structured_response()` formats `data['product']`.

---

## 3. Root Cause Analysis

### Root Cause of Issue 1 (Stale Product Response)

The bug is caused by a **three-fold flaw** in intent classification, context slot merging, and fallback response rendering:

1. **Missing Keyword Pattern in `ai/intent.py`**:
   In `IntentClassifier.classify()`, the pattern rule for `SHIPMENT_INQUIRY` includes phrases like `"courier tracking number"`, `"shipment for"`, `"estimated delivery date"`, but **does NOT include `"where is my shipment"`** or `"shipment"`. Consequently, `"Where is my shipment?"` fails to match the `SHIPMENTS` intent category.

2. **Unconditional Context Slot Merging in `ai/intent.py`**:
   At the start of `IntentClassifier.classify()`, any active `context_slots` (e.g. `product_id="PROD-001"` from Turn 1) are unconditionally merged into `entities`.

3. **Context Slot Hijacking in `PRODUCT_INQUIRY` Classification**:
   In Step 11 of `IntentClassifier.classify()`, the condition for `PRODUCT_INQUIRY` is `if "product_id" in entities or ...`. Because `product_id` was merged from context, this condition evaluates to `True` for **any query that fails steps 1–10**, causing the system to misclassify the shipment query as a `PRODUCT_INQUIRY`.

4. **Fallback Rendering in `ai/response.py`**:
   `synthesize_structured_response()` renders `data['product']` whenever present in `structured_data`, masking the failure to fetch shipment details.

### Root Cause of Issue 2 (Product MRP Becomes Zero)

The bug is caused by a **database schema omission in MySQL**:

1. **MySQL Database Schema**:
   Inspection of the `products` table in the `supporthub_business` MySQL 8.0 database (`DESCRIBE products;`) revealed that the table columns are:
   `product_id`, `company_id`, `seller_id`, `category_id`, `name`, `brand`, `description`, `price`, `stock_quantity`, `specifications`, `created_at`.
   
   **The `mrp` column is completely missing from the MySQL `products` database table.**

2. **Data Mapping in `data_access/mysql_repository.py`**:
   In `MySQLRepository.map_product()`, `row.get("mrp")` executes against the query dictionary resulting from `SELECT * FROM products`. Because `mrp` does not exist in the database table, `row.get("mrp")` returns `None`.

3. **Default Value Coercion**:
   `_to_float(None)` converts `None` to `0.0`. Thus, `Product.mrp` is set to `0.0` for all products retrieved from MySQL, causing `ai/response.py` to calculate `Discount: 0.0%` and output `MRP: ₹0.00`.

## 5. Problem Independence & Security Integrity

- **Independence**: The two issues are **completely independent**. Issue 1 is an intent routing and context slot inheritance bug. Issue 2 is a MySQL database schema missing column bug.
- **Security Boundaries**: **100% INTACT**. Neither bug bypasses customer identity scoping (`customer_id` authorization), anti-IDOR protections, or prompt injection security validators. Cross-customer data isolation remains fully enforced.

---

## 6. Severity & Recommended Remediation (Non-Modifying)

### Issue 1 (Stale Shipment Response)
- **Severity**: **HIGH**
- **Recommended Fix**:
  1. Add `"where is my shipment"`, `"where is my package"`, `"shipment status"`, `"my shipment"` to `SHIPMENT_INQUIRY` pattern rules in `ai/intent.py`.
  2. Do not merge context slots into query `entities` prior to intent category determination.
  3. Ensure `synthesize_structured_response` checks intent intent name before falling back to rendering product objects.

### Issue 2 (Product MRP Zero)
- **Severity**: **MEDIUM**
- **Recommended Fix**:
  1. Alter MySQL table schema: `ALTER TABLE products ADD COLUMN mrp DECIMAL(10,2) AFTER price;`.
  2. Update database migration script to import `mrp` values from `output/products.json`.
  3. Verify `MySQLRepository.map_product()` correctly reads `row.get("mrp")`.
