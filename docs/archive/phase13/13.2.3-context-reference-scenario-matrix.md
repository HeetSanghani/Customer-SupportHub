# Phase 13.2.3 — Scenario Matrix

All scenarios use `CUST-001` as the authenticated customer.  
Where an "earlier order turn" precondition exists, Turn 1 = `"What is the status of ORD-025?"`.

| SC | Query Sequence | Expected | Actual | Status | Notes |
| :---: | :--- | :--- | :--- | :---: | :--- |
| **SC1** | `ORD-025` → `PROD-002` → `"What is its price?"` | Product PROD-002 | **Order ORD-025** | ❌ FAIL | Known failure. Root cause confirmed. |
| **SC2** | `ORD-025` → `PROD-002` → `"Is it available?"` | Product PROD-002 | **Order ORD-025** | ❌ FAIL | Same root cause as SC1. |
| **SC3** | `ORD-025` → `PROD-002` → `"What is its MRP?"` | Product PROD-002 | **Order ORD-025** | ❌ FAIL | Same root cause as SC1. |
| **SC4** | `ORD-025` → `"What carrier is handling it?"` | Order ORD-025 | Order ORD-025 | ✅ PASS | `_context_only_order=True` fires correctly (no product in context). |
| **SC5** | `ORD-025` → `"What is its total?"` | Order ORD-025 | Order ORD-025 | ✅ PASS | Same as SC4. |
| **SC6** | `ORD-025` → `PROD-002` → `"What is the price of PROD-002?"` | Product PROD-002 | Product PROD-002 | ✅ PASS | Explicit `product_id` in Turn 3 overrides context. |
| **SC7** | `ORD-025` → `ORD-025` | Order ORD-025 | Order ORD-025 | ✅ PASS | Same domain, no switching. |
| **SC8** | `ORD-025` → `PROD-002` → `"What is the price?"` | Product PROD-002 | **Order ORD-025** | ❌ FAIL | Same root cause: "price" keyword without explicit ID → no explicit entity → `_context_only_order`. |
| **SC9** | `PROD-002` → `"What about it?"` | Product PROD-002 | No-data fallback | ⚠️ PARTIAL | `product_id` in context but "what about it" has no keywords → `GENERAL_QUERY` / RAG or fallback. Not a security issue. |
| **SC10** | `ORD-003 (denied)` → `"What is its status?"` | Access Denied → No data | Denied → No data | ✅ PASS | `revert_slots()` keeps `active_order_id=None`. Follow-up returns no-data, not a leak. |

### Observations

- **SC1, SC2, SC3, SC8** all fail for the same root cause: `update_slots_domain_aware()` receives merged entities, causing the ORDER domain to overwrite the PRODUCT domain after a product turn preceded by an order turn.
- **SC4, SC5** pass correctly because they are single-domain follow-ups (no product involved).
- **SC6** passes because the explicit `PROD-002` entity in Turn 3 ensures the classifier correctly identifies `PRODUCT_INQUIRY` and the tool uses `product_id` from entities directly.
- **SC9** is a separate, lesser issue: generic pronouns without any product keyword or ID fall through to `GENERAL_QUERY`. This is a usability gap, not a security issue.
- **SC10** confirms security boundaries are intact: unauthorized context is correctly reverted and does not leak.
