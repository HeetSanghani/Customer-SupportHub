# Phase 13.3-09: Hybrid Query Routing Inspection

## Overview
This document evaluates the support for **Hybrid Queries**—queries that require both structured MySQL business data AND unstructured RAG policy documents simultaneously.

---

## Example Hybrid Scenarios

### Scenario A: Order Cancellation Eligibility
- **Query**: `"Can I cancel ORD-025?"`
- **Data Required**:
  1. Structured MySQL Order Status (`orders.status` for `ORD-025`).
  2. Unstructured RAG Cancellation Policy (`POL-003`).
- **Required Synthesis**: If order status is `CONFIRMED` or `PROCESSING` and policy permits cancellation prior to dispatch, inform user that cancellation is eligible.

### Scenario B: Refund Delay & Policy Explanation
- **Query**: `"Why is my refund REF-001 delayed and what is your refund policy?"`
- **Data Required**:
  1. Structured MySQL Refund Record (`refunds.status`, `refunds.created_at` for `REF-001`).
  2. Unstructured RAG Refund Policy (`POL-002` refund timeline details).

---

## Code Inspection & Current Capabilities

### Current State: `PARTIAL / SEQUENTIAL`
- In `ai/orchestrator.py`, if a query contains explicit entities (e.g. `order_id = ORD-025`) and is routed to `STRUCTURED`, tools pull order `ORD-025`.
- If routed to `RAG`, `_execute_tools` updates context slots and retrieves policy chunks.
- Currently, when `use_llm=True`, the LLM response synthesizer receives both the tool data dictionary (`tool_data`) AND the RAG context text (`rag_context`), allowing the LLM to synthesize a hybrid response.
- However, when `use_llm=False`, the deterministic fallback formatter formats EITHER structured tool output OR RAG text, but does not construct a combined single template.

---

## Recommendation for Future Phase
Implement a dedicated `RouteType.HYBRID` in `AIRouter` that explicitly triggers both `ToolRegistry` data retrieval and `RAGPipeline` context retrieval, passing the combined context block to a unified hybrid formatter.
