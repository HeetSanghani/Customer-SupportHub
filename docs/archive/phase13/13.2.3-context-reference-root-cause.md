# Phase 13.2.3 — Root Cause Document

**Final Investigation Status**: `ROOT_CAUSE_IDENTIFIED`

---

## Exact Root Cause

> `AIOrchestrator.process_message()` passes `route_decision.intent.entities` (the **merged** entity dictionary) as `_explicit_entities` to `ConversationContext.update_slots_domain_aware()`. `IntentResult.entities` contains **both** current-query explicit entities AND context-inherited entities. When `update_slots_domain_aware` finds a non-null `order_id` in the merged dict (inherited from context), its `if new_order_id:` branch executes **after** the `if new_product_id:` branch and re-sets `active_order_id = ORD-025` while clearing `active_product_id = None`. The subsequent implicit follow-up query then finds only `order_id` in context, causing `_context_only_order=True` in Step 8 of `classify()` and returning the ORDER response.

---

## Primary Bug Location

| # | File | Component | Line | Defect |
| :---: | :--- | :--- | :--- | :--- |
| 1 | `ai/orchestrator.py` | `process_message()` | 79 | `_explicit_entities = route_decision.intent.entities` — uses MERGED, not explicit-only |
| 2 | `ai/context.py` | `update_slots_domain_aware()` | 126–131 | `if new_order_id:` is independent of `if new_product_id:` — both execute when both keys are non-null in merged dict |

---

## Contributing Design Gap

`IntentResult` (defined in `ai/intent.py`) stores the merged entity dictionary on its `.entities` field. The `classify()` method computes `explicit_entities` internally but does not expose it as a separate field on the returned dataclass. This makes it impossible for the orchestrator to retrieve explicit-only entities from the route decision without re-computing them.

---

## Why Phase 13.2.2 Automated Tests Passed

Phase 13.2.2 `TestGroup8ProductFollowUp.test_product_follow_up_inherits_context` ran:
```
Turn 1: "Tell me about PROD-002."
Turn 2: "What is its price?"
```
This test passed because it used a **fresh conversation** with no prior order turn. `active_order_id = None` throughout, so `update_slots_domain_aware` only saw `product_id` in the merged dict and correctly set `active_product_id = PROD-002`. The test did **not** include a prior order turn as a precondition, so the bug was not exercised.

---

## Recommended Minimal Fix

**Approach A** (preferred — adds explicit_entities field to IntentResult):
1. Add `explicit_entities: Dict[str, Any] = field(default_factory=dict)` to `IntentResult` dataclass in `ai/intent.py`.
2. Populate it in `IntentClassifier.classify()` before returning.
3. In `ai/orchestrator.py` line 79, change:
   ```python
   _explicit_entities = route_decision.intent.entities
   ```
   to:
   ```python
   _explicit_entities = route_decision.intent.explicit_entities
   ```

**Approach B** (no dataclass change):
1. In `ai/orchestrator.py` line 79, change to:
   ```python
   from ai.intent import intent_classifier as _ic
   _explicit_entities = _ic.extract_entities(query)
   ```

Both approaches ensure `update_slots_domain_aware()` receives only entities explicitly present in the current query — not context-inherited ones.

`update_slots_domain_aware()` itself does NOT need to change. Its logic is correct when given the correct (explicit-only) input.
