# Phase 13.2.4 — Contextual Reference Resolution Remediation Plan

## Objective
Fix the contextual reference resolution bug identified in Phase 13.2.3 where contextual pronouns/references (e.g., "its price") in product queries were resolving to prior order context (`ORD-025`) instead of current product context (`PROD-002`).

## Root Cause Summary
`AIOrchestrator.process_message()` passed the merged entity dictionary `route_decision.intent.entities` as `_explicit_entities` to `ConversationContext.update_slots_domain_aware()`. When a product turn was preceded by an order turn, the merged dictionary contained both `product_id` (explicit) and `order_id` (context-inherited). `update_slots_domain_aware()` executed the order update branch second, clearing `active_product_id` and re-persisting `active_order_id`.

## Target Changes
1. **`ai/intent.py`**: Add `explicit_entities` field to `IntentResult` dataclass to expose current-query-only entities separately from merged entities. Populate this field across all classification paths in `IntentClassifier.classify()`.
2. **`ai/orchestrator.py`**: Update `_explicit_entities` line 79 to use `route_decision.intent.explicit_entities` instead of `.entities`.
3. **`tests/test_phase13_2_4_context_reference.py`**: Implement a comprehensive test suite covering Test Groups A–J, critical scenarios 1–5, and regression checks.

## Boundaries
- `ai/context.py` and `update_slots_domain_aware()` will NOT be modified.
- No database, RAG, security rule, or API router changes.
