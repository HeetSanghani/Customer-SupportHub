# Phase 13.3-02: Authentication & Session Flow Inspection

## Overview
This document traces the authentication architecture of Customer-SupportHub implemented in `supporthub/backend/app/routers/auth.py` and `supporthub/backend/app/dependencies.py`.

---

## Registration Flow (`/auth/register`)
- **Input**: `email: EmailStr`, `name: str`, `password: str` (min length 8).
- **Validation**:
  - Checks if `email` already exists in `users` table. If exists, raises HTTP 400 (`Email already registered`).
  - Hashes password using `bcrypt` salt rounds (`hash_password()`).
  - Assigns `role = UserRole.customer` and `status = UserStatus.active`.
- **User Record Created**: SQLModel `User` instance inserted.
- **Tokens Issued**:
  - `access_token`: HS256 JWT signed with `SECRET_KEY`, contains `sub: user_id`, `role`, and `exp` (default 30 mins).
  - `refresh_token`: HS256 JWT containing `sub: user_id`, `type: "refresh"`, and `exp` (default 7 days).
- **Default `customer_id` Mapping**: Newly registered users have `customer_id = NULL` by default.

---

## Login Flow (`/auth/login`)
- **Input**: Form data (`username` = email address, `password`).
- **Validation**:
  - Look up user by `User.email == form.username`.
  - Verify password hash using `bcrypt.checkpw()`.
  - Check account status: if `suspended`, raises HTTP 403.
- **Output**: Returns `TokenResponse` with `access_token`, `refresh_token`, `role`, `user_id`, and `name`.

---

## Token Refresh & Current User Inspection
- **`/auth/refresh`**: Decodes refresh token, validates `type == "refresh"`, verifies active user status, and issues fresh access and refresh token pair.
- **`/auth/me`**: Decodes Bearer token from header via `get_current_user` dependency, returns `MeResponse` including `id`, `email`, `name`, `role`, `status`, `avatar_url`, and `customer_id`.

---

## Key Authentication Findings
1. **JWT Contents**: Claims include `sub` (User UUID) and `role`. It does **not** embed `customer_id` inside the JWT payload itself; `customer_id` is retrieved live from the database via `User` entity lookup.
2. **Missing Customer ID**: When a user registers without linking to a ShopKart customer ID, `user.customer_id` is `None`.
